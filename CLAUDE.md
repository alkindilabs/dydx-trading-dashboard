# dYdX Trading Dashboard - Development Notes

How the system is built (module layout, indexer access, load cycle, attribution boundary, caching, status badge, deployment, test harness) is in `ARCHITECTURE.md`; this file holds contributor rules and metric definitions.

## Chart Explanations

### Trading Activity by Market
The Trading Activity chart (doughnut chart on Overview tab) shows:
- Distribution of your trades across different markets (ETH-USD, BTC-USD, etc.)
- Each slice size = number of trades in that market (CLOSED count)
- Labels show market name and trade count, followed by the open count only when it is non-zero (`+ N open`) or unknown (`+ — open` while the OPEN rows are unknown)
- Legend shows percentage of total trading activity
- Hover tooltip displays:
  - Number of trades and percentage
  - Profit for that market labeled "Profit (incl. funding − fees)" = FIFO realized + FIFO unrealized of the lots left open (at the oracle) + netFunding − fees across every fill in the market (same definition as Performance-by-Asset PROFIT column AND the Total Profit headline); reads `— (reason)` when that market's profit is gated, with the same reason as the asset table
  - Number of open positions when non-zero, or `— (reason)` while the OPEN rows are unknown
- Shows top 5 most traded markets
- Helps identify trading focus and diversification

## Dashboard Components

### Important Rules
1. Never show demo/fake data
2. Always require real dYdX address
3. Display "—" when no data available (or "Data not available" caption when the metric itself is unimplemented)
4. Auto-load from URL if address parameter present
5. **No metric is better than a wrong metric.** If a number can't be computed correctly from available data, render `—` and label "Data not available". Do not invent placeholder formulas.
6. **Bump `SCHEMA_VERSION` in `portfolio-cache.js` whenever the response shape or row order of a cached field changes** (including a change to how `/fills` is fetched or ordered), so snapshots written by older code read as a miss.

## Metric Definitions (single source of truth)

**Compute trade classification, returns, drawdowns and sample adequacy only through `RiskMetrics` (`risk-metrics.js`); never recompute them inline in `index.html` or a panel.** When semantics change, update the helper AND this section in the same commit.

### Per-position attribution (fills → positions)
Why per-position values come from `/fills`, where the attribution runs and the fill order it relies on: `ARCHITECTURE.md`, Per-position attribution. The matching rules and output:

`RiskMetrics.attributeFillsToPositions(positions, fills)` runs one FIFO walk per market over all fills, splitting each fill into a closing and an opening portion (a reversing fill has both). The walk yields segments (net size leaves 0 … returns to 0, or reverses); a segment belongs to the position whose `createdAt` equals its first fill's, otherwise to the earliest position whose `[createdAt, closedAt]` window contains it. When several positions share that millisecond (one was opened and reversed, or closed and reopened, within a block), the segment goes to the earliest-closing one on the segment's side that has no segment yet (OPEN counts as closing last), so the chain order of segments, not the order the indexer listed the positions in, decides; same-side positions that also share `closedAt` cannot be told apart and are all marked incomplete. Net size counts as flat within `max(1e-9, 1e-12 × the largest of the net size before the fill, the fill size and the peak |net size| since the market was last flat)` base units: summed decimal fill sizes leave binary-float residue that grows with magnitude and stays behind after the position is scaled down, and a tolerance measured only against the current fill turned that residue into a phantom reversal that made the position and every later one in the market incomplete. A reversing fill's closing portion belongs to the older position and its opening portion to the newer one. It returns `Map<position, { realized, fees, profit, peakSize, entryVwap, exitVwap, fillCount, complete, incompleteCause, openedByFlip, closedByFlip, openSizeDisagrees }>`:
- `realized` — FIFO realized on the position's closing portions (gross, no fees)
- `fees` — `fill.fee` on its portions, a reversing fill's fee split pro-rata by size (positive = paid, negative = rebate)
- `profit = realized − fees` (funding excluded; it stays on the indexer's `netFunding`)
- `peakSize` — max |net size| during the segment, base units, always positive
- `entryVwap` / `exitVwap` — size-weighted price of the opening / closing portions
- `fillCount` — fills touching the position (a reversing fill counts for both)
- `openedByFlip` / `closedByFlip` — the position was opened / closed by a reversing fill
- `complete = false` when fills are missing, no segment (or more than one) matched, the segment's side disagrees with the position's, a CLOSED position's segment did not return to flat by its `closedAt` (a return exactly at `closedAt` counts; a later one means the closing fill is missing and the later fill may belong to a position absent from the list), same-side positions sharing both `createdAt` and `closedAt` made the match ambiguous, one of its segments starts or ends with a reversing fill that has no listed partner (a segment the walk opened by a flip needs an opposite-side position whose `closedAt` equals the segment's start; one it closed by a flip needs an opposite-side position whose `createdAt` equals the reversal moment; a missing partner means a fill is missing and the walk's net size is off; private `flipPartnersListed`), a fill the walk cannot use (unparseable `price` / `size` / `side`) lies inside the window (a fill with no parseable `createdAt` counts as inside every window in its market), or an OPEN position's indexer `size` (signed, negative for a SHORT; OPEN rows carry a reliable size) differs from the signed net size the walk ends its market on by more than the walk's flat tolerance, or is missing (private `openSizeMatchesWalk`; a missing fill before the position can shift the walk's size without changing its side or flips). `complete` is `true` exactly when `incompleteCause` is `null`.
- `incompleteCause` — `null` when complete, otherwise the value of the frozen `RiskMetrics.INCOMPLETE_CAUSE` naming why, a phrase a panel can show as is. In precedence order (when several apply, the first wins): `UNUSABLE_FILL` 'Unusable fill', `REVERSAL_PARTNER_MISSING` 'Reversal partner missing', `INDISTINGUISHABLE` 'Indistinguishable positions', `NO_MATCHING_FILLS` 'No matching fills' (also the cause when fills are missing), `FLAT_MID_POSITION` 'Fills go flat mid-position' (more than one segment matched), `SIDE_MISMATCH` 'Fills on the opposite side', `NOT_FLAT_AT_CLOSE` 'Fills not flat at close', `OPEN_SIZE_MISMATCH` 'Fills do not match open positions'. The open-size case is last because a skipped or missing fill usually also makes the size disagree, and the root cause is the more useful message. The open-position gate reads it (see Total Profit, Open-position gate).
- `openSizeDisagrees` — true for an OPEN position whose indexer `size` differs from, or cannot be compared with, the walk's final net size, whatever else made it incomplete (an unusable fill that also shifts the size leaves `incompleteCause` at 'Unusable fill' and this flag `true`): the market's fills do not add up to the open position, so the market's FIFO totals are off too. `false` for every other position, including an OPEN one incomplete only for another reason. No panel reads it; the open-position gate keys off `incompleteCause`. A position with no matched segment carries `realized = fees = profit = 0` and null size / prices.

`RiskMetrics.oppositeSide(side)` is the one side-flip rule: `'SHORT'` for `'LONG'`, `'LONG'` for `'SHORT'`, `null` for anything else (case-sensitive; callers upper-case first). The attribution's reversal-partner check and the Positions board's flip-tag tooltip both use it.

`RiskMetrics.hasCompleteAttribution(p)` is the one completeness rule: only `complete === true` counts, so a position with no attribution fields at all is incomplete. The classifier, `peakNotional` / `tradeReturn`, the Positions board, the Behavior double-down detector and the Tax report all call it. `RiskMetrics.timestampMs(iso)` is the one timestamp parser (null when absent or unparseable) the attribution and the Tax report window fills with.

### Trade classification
A position with `status === 'CLOSED'` is bucketed by its fill-attributed `profit` (net of fees, excluding funding):
- `> 0` → **win**
- `< 0` → **loss**
- `== 0` → **scratch**

`decisiveCount = winCount + lossCount` (excludes scratches). Use `decisiveCount` as the denominator for win-rate-style ratios so the same value never reads two ways across cards.

**All-or-nothing, account-wide.** A closed position without complete attribution (`hasCompleteAttribution`) lands in `incomplete`; while any exists, every derived field (`winRate`, `profitFactor`, `avgWin`, `avgLoss`, `expectancy`, `payoff`, `breakevenWinRate`, `bestTrade`, `worstTrade`) is `null` and `incompleteReason` reads e.g. "3 positions missing fill data". The optional `unavailableReason` argument does the same for a CLOSED list that is itself unknown: `processData()` passes the CLOSED list's missing-input reason (`ARCHITECTURE.md`, Missing inputs), so an unavailable list reads as that reason rather than as an account with no trades. Consumers test `incompleteReason !== ''`. Win Rate, Profit Factor, Avg Win, Avg Loss, Payoff, Expectancy, Kelly (its caption), the Strategy Edge verdict, streaks, win-rate trend, the Win/Loss and Position Size distributions, the per-trade Sharpe fallback and the Behavior tab's profit-based cards then render `—` with that reason (an empty bucket reads `N/A` instead); the activity heatmap shows the reason when the CLOSED list is unavailable. The Monthly and Performance-by-Asset tables follow the account: `processData()` passes the account classifier's `incompleteReason` to `renderTables` (`gaps.classifier`), which hands it as `unavailableReason` to `classifyByMonth(positions, unavailableReason)` and to each per-asset `classifyClosed`, so one incomplete position anywhere blanks every month's and every asset's ratios (and the per-asset Sharpe) together with the header cards. Their TRADES cell reads `decisive (+scratches)`, the plain closed count with the reason on hover while the account holds an incomplete position, or `—` with the reason when the CLOSED list is unavailable.

Helper: `RiskMetrics.classifyClosed(positions, unavailableReason = '')` returns `{ wins, losses, scratches, incomplete, all, grossWin, grossLoss, totalProfit, winCount, lossCount, scratchCount, decisiveCount, closedCount, incompleteCount, incompleteReason, winRate, profitFactor, avgWin, avgLoss, expectancy, payoff, breakevenWinRate, bestTrade, worstTrade }`. `totalProfit = grossWin − grossLoss` (fill-attributed, net of fees); `payoff = avgWin / avgLoss`; `breakevenWinRate = 100 / (1 + payoff)`, the win rate (percent) at which expectancy is zero; `bestTrade` is the single largest winning `profit` and `worstTrade` the single most negative losing `profit` (kept negative), each `null` without a win / loss and, like every derived field, while `incompleteReason` is set. The Payoff cards, the Strategy Edge's implied payoff and Kelly (`winRate / 100 − (1 − winRate / 100) / payoff`) read these fields rather than re-deriving them; the two Payoff captions take their "WR x% vs y% breakeven" text and tone from `Format.breakevenVerdict(winRate, breakevenWinRate)` (profit tone from the breakeven rate up). Avg Win, Avg Loss and Expectancy cells take their colour from `Format.signClass`, so a negative expectancy reads as a loss. The percent unit is `AppConstants.PERCENT`.

### Per-trade return
`r = profit / peakNotional`, where `peakNotional = peakSize × entryVwap` — profit as a fraction of the peak notional held during the position, all from `attributeFillsToPositions`. Peak notional, not cumulative entered size, which overstates capital on scaled positions. Used for per-trade Sharpe (fallback), asset-level Sharpe, the Win/Loss Distribution and the Positions board's PROFIT % so they never disagree. Helpers: `RiskMetrics.peakNotional(p)` (null when the attribution is incomplete or either factor is not positive; also the Position Size Distribution's size and the Behavior double-down detector's size) and `RiskMetrics.tradeReturn(p)` (null when the attribution is incomplete or the notional is undefined).

### Total Profit (headline)
`totalPnL = FIFO realized over /fills + FIFO unrealized of the lots left open + Σ netFunding over every position − Σ fees over every fill`. Realized is computed **bottom-up from /fills via FIFO inventory walk** (`computeRealizedFromFills`), NOT from `/perpetualPositions.realizedPnl` (why: `ARCHITECTURE.md`, Per-position attribution). FIFO over the raw fill records reconciles to the equity-based curve within float-rounding. The Total Profit hero card surfaces the split as a three-cell ledger:

- **TRADING** = `computeRealizedFromFills(fills).total + computeUnrealizedFromFills(fills, marketsMap).total`. Unrealized is the lots the same FIFO walk leaves open, marked at `marketsMap[market].oraclePrice`, NOT the indexer's per-position `unrealizedPnl`: that field marks against the average entry of every opening fill, a different cost basis from FIFO realized, so adding the two double-counts profit FIFO has already realized on a partly reduced position, a material headline error on any account that scales out of positions.
- **FUNDING** = `netFundingTotal(positions)` — positive contribution when received, negative when paid
- **FEES** = `−feesTotal(fills)` — displayed as a *signed contribution to profit*. dYdX `fill.fee` is positive when the user paid (taker / most maker fills) and negative for maker rebates, so the cell renders the paid amount as a negative dollar value (red) and rebates as positive (green)

Headline math: `TRADING + FUNDING + FEES_contribution`.

**Missing inputs.** A component whose inputs did not load (`ARCHITECTURE.md`, Missing inputs) renders `—`: TRADING needs `/fills` and an oracle price for every market with open lots (else the markets endpoint's missing-input reason or "No oracle price for …"), FUNDING needs the OPEN rows (`openPositionsGap`) and the CLOSED list, FEES needs `/fills`. Any `—` component blanks the headline too, with the reason as its caption, and skips the reconciliation guard. `processData()` derives these from the per-input reasons as `profitLedgerGaps(allData, inputs, openPositionsGap, unpricedMarkets, fillGapsByMarket)` in `index.html` and passes them on so Performance by Asset and the Overview chart tooltip blank the same components. `unpricedMarkets` is `computeUnrealizedFromFills(...).unpricedMarkets`; `unpricedReason(data, markets)` words their gap: '' for none, else the markets endpoint's missing-input reason or "No oracle price for A, B".

**Open-position gate.** Fills that loaded can still be short. `fillGapsByMarket` maps each affected market to one reason:
- any OPEN position whose attribution is incomplete (`RiskMetrics.hasCompleteAttribution` false): `incompleteOpenPositionReason(p)` gives "<incompleteCause> in <market>" (e.g. "Unusable fill in BTC-USD", "Reversal partner missing in BTC-USD"), except the open-size cause, which reads "Fills do not match open positions" alone. The first such position in a market names that market's reason;
- while the OPEN rows are known, a market whose fills end with open lots (`computeUnrealizedFromFills(...).openMarkets`) but lists no OPEN row (a closing fill is missing, so the lots are phantom): "Fills do not match open positions".

That wording is `OPEN_SIZE_MISMATCH_REASON` in `index.html`, taken from `RiskMetrics.INCOMPLETE_CAUSE.OPEN_SIZE_MISMATCH` so it is defined once. TRADING reads `—` with the fills reason when `/fills` failed, otherwise with the unpriced reason followed by each distinct `fillGapsByMarket` reason, joined with "; "; the headline takes the first gap of TRADING, FUNDING, FEES as its caption. Per-market profit is scoped to its market: `profitLedgerGaps(...).marketProfit(market)` is the fills reason, else that market's `fillGapsByMarket` reason, else that market's own unpriced reason (`unpricedReason(data, [market])`), else the FUNDING gap. A gap in one market blanks only that market's Performance-by-Asset PROFIT and Overview chart tooltip profit; other markets, FUNDING and FEES stay numeric.

Helpers:
- `RiskMetrics.computeRealizedFromFills(fills)` — `{ total, byMarket }` from FIFO inventory walk; handles position flips atomically (closes current lots, opens fresh opposite-side inventory at the flip-fill price for residual size)
- `RiskMetrics.netFundingTotal(positions)` — funding component
- `RiskMetrics.feesTotal(fills)` — sum of `fill.fee` (positive = paid)
- `RiskMetrics.marketFees(fills)` — `{ [market]: feesPaid }` map for the per-asset table
- `RiskMetrics.computeUnrealizedFromFills(fills, marketsMap)` — `{ total, byMarket, unpricedMarkets, openMarkets }`; `openMarkets` lists every market whose walk ends with open lots; a flat market contributes 0, a market with open lots and no positive oracle price is `null` in `byMarket` and listed in `unpricedMarkets`, and `total` is then `null`. Realized + unrealized equals the fills' cash flow plus the marked inventory.
- `RiskMetrics.equityAdjustedTotalPnl(historicalPnl, equityNow)` — the guard's reference (below)

A reconciliation guard fires (`console.error`) when `|headline − reference| > max($1, |reference|×1%)`, where the reference is `equityAdjustedTotalPnl`: the latest `/historical-pnl` `totalPnl` moved by the subaccount's equity change since that row (the rows are hourly, so the raw latest row lags the live headline by the price drift since it; the adjustment assumes no transfer since the row). On an account with complete `/fills` to inception the headline and the reference agree within float rounding, so the guard is expected to stay quiet there, but an equity flow the indexer does not expose per event (rewards, insurance fund, ADL) can still open a gap of a few percent; if it fires, the structured payload (trading / funding / fees / equityBased / gap / row counts / activeChildSubaccounts) tells the operator which stream to inspect.

Classification (`classifyClosed`) buckets by the fill-attributed per-position `profit` (see Per-position attribution), cut from the same per-market FIFO walk as `computeRealizedFromFills`; the classifier's figures are net of fees, the headline additionally carries funding and unrealized.

### Per-market Profit
`total = realized (FIFO from /fills) + FIFO unrealized of that market's open lots + netFunding across every position in that market − fees on fills in that market`. Used by the Overview chart tooltip AND the Performance-by-Asset table, which follow the headline's missing-input rule (PROFIT / FUNDING / FEES read `—` when their inputs did not load; PROFIT also reads `—` for a market under the open-position gate or with open lots and no oracle price, with that market's reason). While `openPositionsGap` is set, the table lists every market rather than hiding one with no known position. Helper: `RiskMetrics.marketPnL(positions, feesMap?, realizedByMarket?, unrealizedByMarket?)` (returns `{ realizedClosed, unrealizedOpen, netFunding, fees, total, closedCount, openCount }`).

- `feesMap` is optional `{ [market]: feesPaid }` (positive = paid). Omitting it leaves `fees` at 0.
- `realizedByMarket` is optional `{ [market]: realized }` from `computeRealizedFromFills(...).byMarket`. When provided, it OVERRIDES the sum of the per-position indexer `realizedPnl` field as the source for `slot.realizedClosed`. Omitting it falls back to that indexer sum (`ARCHITECTURE.md`, Per-position attribution, says why production never does).
- `unrealizedByMarket` is optional `{ [market]: unrealized }` from `computeUnrealizedFromFills(...).byMarket`. When provided, it OVERRIDES the sum of the indexer `unrealizedPnl` of OPEN positions as `slot.unrealizedOpen` (a `null` entry adds 0; the caller blanks PROFIT through the TRADING gap).

The Performance-by-Asset table's AVG PROFIT column is the per-asset classifier's `expectancy`. BEST / WORST are single trades, not averages: the per-asset `classifyClosed` result's `bestTrade` / `worstTrade` (fill-attributed, net of fees, excluding funding; see Trade classification). WORST renders as a negative dollar figure. Each reads `—` when the asset has no trade of that kind, and both read `—` while the classifier's `incompleteReason` is set (all-or-nothing, see Trade classification).

### Monthly Performance Breakdown — PNL column
`PNL = lastOfMonth.totalPnl − lastOfPriorMonth.totalPnl` from `/historical-pnl`. Same series as headline drawdown and MAX DD on the row, so the column is dimensionally consistent with every other monthly column. Helper: `RiskMetrics.histPnlMonthly(historicalPnl)` returns `{ [monthKey]: { delta, hasData } }`. Months with no `/historical-pnl` rows render `—` (no-metric > wrong-metric). The earliest observed month gets `delta = firstRow.totalPnl − 0`, which overstates that first month if the `/historical-pnl` series does not start at the account's inception; the dashboard does not flag that case. Win Rate / Avg Win / Avg Loss / Profit Factor in the same row come from `RiskMetrics.classifyByMonth` (fill-attributed `profit`); while any closed position in the account is incomplete, or the CLOSED list is unavailable, every month renders them `—` (see Trade classification).

### Headline Max Drawdown
$ DD on cumulative `totalPnl` from `/historical-pnl` (realized + unrealized profit over time, excluding net transfers). Peak-to-trough in chronological order. This series captures unrealized peaks the closed-trade ledger cannot see (e.g. a large open profit that was later given back). Helper: `RiskMetrics.histPnlDrawdown(historicalPnl)`.

Falls back to trade-system $ DD on cumulative fill-attributed `profit` (`RiskMetrics.tradeSystemDrawdown(positions)`) when historical-pnl is unavailable OR when it produced no positive drawdown (an empty/monotonic series). The fallback is all-or-nothing like the classifier: while any closed position is incomplete (or the CLOSED list is unavailable) the cumulative series is empty, so Max Drawdown, Current Drawdown and Recovery Factor render `—` with the classifier's `incompleteReason` and the Drawdown Periods table stays empty. The Recovery Factor and Drawdown Periods table follow the same fallback rule so all drawdown-derived cards stay aligned.

The Drawdown Periods table enumerates every peak→trough→recovery event on the same `totalPnl` curve via `RiskMetrics.histPnlDrawdownEvents(historicalPnl)` (with the same trade-system fallback). The Monthly Performance Breakdown's MAX DD column applies `histPnlDrawdown` to that month's slice, so it shares the headline's definition.

The Recovery Factor card is the latest value of the series the headline drawdown was measured on ÷ that drawdown, taken from the Current Drawdown result on the same source (`cdd.currentValue`): latest `totalPnl` on the historical-pnl path, cumulative closed-position `profit` on the fallback path. The numerator and denominator never come from different profit series.

### Current Drawdown
`$ DD = max(0, peak − latest)` on the same `totalPnl` series as Headline Max Drawdown — the two cards always share their P&L stream so they cannot disagree about which side of the ledger is being measured. `0` means the account is at-or-above its prior peak; positive value means the account has given back that many dollars since the peak. Helper: `RiskMetrics.histPnlCurrentDrawdown(historicalPnl)` returns `{ dollarDrawdown, pctOfPeakProfit, peakAt, peakValue, currentAt, currentValue, n, hasData }`.

Falls back to `RiskMetrics.tradeSystemCurrentDrawdown(closedPositions)` (cumulative fill-attributed `profit`) using the same `drawdownSource` decision as Max Drawdown — if the hist path was skipped for the max card, it's skipped for the current card too. `hasData: false` on an empty series → render `—` with "No equity series available".

Visual states on the card:
- `hasData = false` → `—`, detail "No equity series available" (or "No closed trades", or the classifier's `incompleteReason` on the fallback path)
- `dollarDrawdown ≤ 0` → `$0`, green (profit class), detail "At peak (YYYY-MM-DD)"
- `dollarDrawdown > 0` → `−$X`, red (loss class), detail "Nd below peak (since YYYY-MM-DD) · Y.Y% of peak"

The "days below peak" duration is derived inline from `peakAt`/`currentAt` timestamps (rounded to whole days). `pctOfPeakProfit` is suppressed when peak ≤ 0 (no positive peak profit to denominate against).

### Drawdown of arbitrary equity series
Use `RiskMetrics.validDrawdownFromEquity(equityArray)` for the Calmar denominator on TWR wealth (and the per-trade Calmar fallback's compounded wealth); the headline drawdown does not use it. Returns `null` when peak ≤ 0 OR trough < 0 — these are synthetic-equity artifacts that arise when the inception-time principal proxy goes under zero (e.g. a wipe followed by a redeposit). Filtered drawdowns must render as `—`.

### Sample-adequacy gate
A statistical metric (Sharpe, Sortino, Calmar, VaR, CVaR, monthly Sharpe) renders `—` unless the time-weighted-return sample passes ALL three constants (defined in `risk-metrics.js`):
- `MIN_RETS = 30` (at least 30 valid TWR returns)
- `MIN_YEARS = 1/12` (at least one month of valid coverage)
- `MIN_COVERAGE = 0.5` (at least half the historical-pnl rows produced a valid return — protects against post-wipeout sample bias)

Helper: `RiskMetrics.assessAdequacy(returns, timestamps, histLength)` → `{ adequate, reason, ppy, years, coverage, n }`. The same gate fires for Sharpe/Sortino/Calmar AND VaR/CVaR — the dashboard never shows VaR for a sample window that's too short to support Sharpe.

When the time-series gate fails, Sharpe/Sortino/Calmar fall back to `AppPanels.performance.computeTradeBasedMetrics(cls)` (a `classifyClosed` result), which annualizes Sharpe/Sortino over `RiskMetrics.tradeReturn` of every decisive closed trade (√ trades-per-year, years of `AppConstants.MS_PER_YEAR`) and derives Calmar from their compounded wealth curve. It and the per-asset Sharpe column (`computeAnnualizedTradeSharpe(cls, minN)`) take their returns and annualization from one private helper, `tradeReturnSample`. Like the classifier it is all-or-nothing: while the classifier's `incompleteReason` is set it returns `{ ok: false, reason }` and the cards render `—` with that reason. VaR/CVaR have no fallback — they render `—` with the gate reason.

### Cross-margin liquidation price
dYdX is cross-margin. Per-position liq price assumes OTHER open positions hold their current unrealized profit contribution — exact for single-position accounts; isolation approximation otherwise. Derivation: at liquidation, account equity equals maintenance margin requirement computed off liquidation-price notional (`MMR = |size| × P_liq × MMF`).
- LONG:  `P_liq = (size × oracle − equity) / (size × (1 − MMF))`
- SHORT: `P_liq = (equity + oracle × |size|) / (|size| × (1 + MMF))`

Helper: `RiskMetrics.crossMarginLiqPrice(position, subaccount, marketsMap)` returns `null` when MMF / size / equity unavailable.

The Liquidation Risk Analysis table's LEVERAGE column shows `notional / subaccount.equity`. Per-position equity does not exist on the dYdX API.

**Missing OPEN list.** `renderLiquidationTable` and `renderLeverageUtilization` in `src/panels/risk.js` take `processData()`'s `openPositionsGap` (`ARCHITECTURE.md`, Load cycle and application state) as a trailing argument. While it is set, the Liquidation table holds a single full-width row with the reason, so an unknown list never reads as an account without open positions.

**Leverage card states.** The private `leverageReading` in `src/panels/risk.js` picks the value and its `#leverageUtilDetail` caption, first match wins:
1. `openPositionsGap` set → `—`, caption the reason (even when some OPEN rows are present, and even when equity is also missing)
2. `RiskMetrics.usableEquity(subaccount)` null → `—`, caption "Equity unavailable"
3. no OPEN position → `0.00x`, caption "No open positions"
4. an OPEN position `RiskMetrics.positionNotional` cannot value (no price or size) → `—`, caption "Open position notional unavailable", even beside priced ones: a sum over the others would understate leverage
5. otherwise `RiskMetrics.leverageUtilization` under the markup's default caption ("Notional ÷ equity"), which also returns once a later load clears the reason.

**Usable equity** has one definition, `RiskMetrics.usableEquity(subaccount)`: the subaccount's equity when positive, else `null` (no subaccount, missing, unparseable, zero or negative). `crossMarginLiqPrice`, `leverageUtilization`, `liquidationRow`'s `lev` and the Leverage card all gate on it.

**Open notional** has one definition, `RiskMetrics.positionNotional(position, marketsMap)` = `|size| × price` with price `position.oraclePrice || marketsMap[market].oraclePrice || position.entryPrice` (mark-based, matches dYdX's official UI; position objects from `/perpetualPositions` do **not** carry `oraclePrice`, which lives on `marketsMap[market].oraclePrice`); `null` without a positive size and price. It needs no subaccount. `RiskMetrics.leverageUtilization(positions, subaccount, marketsMap)` (the Risk-tab Leverage card: Σ notional ÷ equity), `RiskMetrics.liquidationRow(position, subaccount, marketsMap)` (per row: `{ size, entry, oracle, notional, lev, liq, distancePct }`) and the Positions board's Active Positions card all use it, so they never diverge. The oracle has no entry fallback: `crossMarginLiqPrice`, `liquidationRow`'s `oracle` (0 without one), `liq` and `distancePct` (null without one) need an oracle price. All are unit-tested in `test/risk-metrics.test.js`.

**Compute tax-year figures only through `TaxReport` (`tax-report.js`) and FX rates only through `FxRates` (`fx-rates.js`); never inline in `index.html` or in `src/panels/tax.js`.** When semantics change, update the helper AND this section in the same commit.

### Year boundary
A closed position belongs to tax year `Y` iff `new Date(position.closedAt).getUTCFullYear() === Y`. UTC is mandatory: Portuguese local time (WET/WEST) would misclassify late-Dec UTC trades.

Helper: `TaxReport.closedAtYearUTC(position)` returns `null` for invalid timestamps.

### Realized P&L and fee source — per-position fill attribution
`buildYearReport` takes each row's `realizedPnlUSD` and `feesUSD` from `RiskMetrics.attributeFillsToPositions`, run once over every position (OPEN included, so an open position's fills are never claimed by a closed one) and the entire fills array: one continuous FIFO walk per market, never restarted at position boundaries, so year totals reconcile to the equity curve. A reversing fill's realized goes to the position it closes and its fee is split pro-rata by size between the two positions (see Per-position attribution); the split moves fee between the two rows, so a year's total changes only when the rows close in different years or the newer one is still open.

**Incomplete attribution.** A row whose attribution is not `complete` carries `_attributionIncomplete: true` and `realizedPnlUSD = feesUSD = netUSD = null` (their EUR mirrors `undefined`): its number could hold another position's fills (e.g. the segment of a position missing from the list lands in the neighbour whose window contains it). `summarize` is all-or-nothing like the classifier: while any row is incomplete (`incompleteCount > 0`) the net, gross gains / losses and fee totals, USD and EUR, are `undefined` rather than a partial sum; funding and the trade count stay. `warnings.incompleteAttributionCount` drives the status line and the warning strip, and the panel renders those cells, totals and the W / L / S split as `—`.

The row's SIZE (PEAK) / ENTRY / EXIT (`peakSize`, `entryPrice`, `exitPrice`, also in the CSV / JSON) are the attribution's `peakSize` / `entryVwap` / `exitVwap`, the values the Positions board shows, and `null` while the attribution is incomplete (private `attributedSizeAndPrices`), even when the incomplete attribution carries segment values: on screen `—`, in the CSV empty cells, in the JSON `null`. On screen the size cell uses the board's formatter (`Format.fmtAssetSize`); prices keep up to 4 decimals (the board rounds to whole dollars) because a tax filing needs them. The CSV and JSON exports round all three to `AppConstants.SIZE_SIGNIFICANT_DIGITS` significant digits (private `atSizePrecision`; the JSON through `exportRow`), the same precision `fmtAssetSize` shows sizes at, so the float noise of summed fills (`0.30000000000000004`) stays out of the files; the row objects and the on-screen table are not rounded. The indexer's fields are not used as a substitute.

**Inputs unavailable.** When `/fills`, the CLOSED list or the OPEN list did not load (`ARCHITECTURE.md`, Missing inputs), `processData()` passes the first reason to the Tax panel (`tax.render(..., dataGap)`): without fills nothing can be computed, and without a position list fills cannot be tied to the right rows. Realized, fees, net and EUR net render `—` per row; the net / gross / fee totals and the W / L / S split render `—`; funding and the trade count still show; the warning strip names the reason; nothing is downloadable and no FX request is made. With no closed rows at all (the CLOSED list failed) the status line shows the reason instead of "No closed positions for this address."

Helper: `RiskMetrics.attributeFillsToPositions(positions, fills)` — see Per-position attribution.

**Row flags.** Incompleteness is carried once: `_attributionIncomplete` (CSV `attribution_incomplete`) is `true` exactly when the attribution is not complete (`RiskMetrics.hasCompleteAttribution`), and `_realizedFillError` (CSV `realized_fill_error`) is its reason, never judged from the indexer window alone: `null` when complete, otherwise the most specific of `'no-fills-in-window'` (no fill of the market inside `[createdAt, closedAt]`), `'invalid-fill-in-slice'` (a fill in that window fails `isFifoUsableFill`), else `'attribution-incomplete'`. `warnings.incompleteAttributionCount` counts the incomplete rows; the report's `warnings` holds only that, `feeAttributionAmbiguousCount` and `missingFxDates`. A complete row is exact even when its window does not net flat in isolation: the two rows of a reversal both hold the reversing fill, yet each is complete and carries only the overlap hint (see Fee attribution). Because any incomplete row blanks the fills-derived year totals, a total that shows is a sum over complete rows only.

**Invalid fills.** The FIFO walk skips fills whose `price`/`size`/`side` won't parse (`RiskMetrics.isFifoUsableFill` is the one definition); `attributeFillsToPositions` marks the positions whose window holds one `complete: false`, so their rows read `—` and blank the totals as above. The row also carries `_hasInvalidFill` (the same predicate over its window's fills; CSV column `invalid_fill_in_window`), and the panel adds an invalid-fill note to that row's † tooltip; no warning counter tallies it. The status line and warning strip read `warnings.incompleteAttributionCount` only: an invalid fill always makes the row incomplete, so the incomplete-attribution message covers it.

**† marks warnings only.** The panel appends † to a row's date cell when the row has a warning: a data gap, incomplete attribution, an invalid fill, or a missing FX rate. Each warning's text goes in the cell's tooltip and `aria-label`. The same-market overlap (below) is an audit hint: its text joins the tooltip and `aria-label`, but it adds no †.

`buildYearReport` always takes realized and fees from `RiskMetrics.attributeFillsToPositions`; nothing is computed per window. Batch path: fills pre-grouped by market and sorted by `createdAtMs` once. Per-position window slicing, which feeds only `fillCount` and `_hasInvalidFill`, uses binary search for `[lo, hi)` bounds (`O(log marketFills + windowSize)` per row). The fill attribution is built once per call (`O(n log n)`, where n is total fills, plus a linear scan of a market's positions for each segment whose first fill matches no position's `createdAt`). Overlap detection is a sort+sweep per market (`O(n log n)` sort, `O(n + total_overlaps)` sweep) that records every chain member (A↔B↔C with A and C not overlapping still marks all three).

### Fee attribution
Per-fill fees on `/v4/fills` are attributed by the **same fill attribution** as realized P&L: each fill portion belongs to exactly one position, and a reversing fill's fee is split by size between the position it closes and the one it opens. **No side filter** — `/v4/fills` exposes side as `BUY`/`SELL` while positions are `LONG`/`SHORT`, AND both sides legitimately belong to a position's lifecycle (BUY opens a LONG / closes a SHORT; SELL closes a LONG / opens a SHORT). A direct side equality check would never match a single fill.

When ANOTHER closed position in the **same market** overlaps the window (regardless of side), the row carries `_feeAttributionWarning=true`. Fees and realized P&L are still attributed uniquely by the fill attribution (no double-count of boundary fills), so the flag is only an audit hint that the windows touch, and the two rows of every reversal carry it (they share the reversing fill's instant). Despite its name it covers **realized P&L as well as fees**; the panel's status line reads "N rows overlap another position's window", the row's date cell explains it in the tooltip without a †, and neither the status line nor the strip calls the row values approximate. Downstream UI / CSV / JSON treat it as a combined attribution hint.

### Net realized P&L (per row)
`netUSD = realizedPnlUSD + netFundingUSD − feesUSD`. Fees always subtract because the attributed `realized` is gross of fees (the FIFO walk looks only at fill prices and sizes).

Helper: `TaxReport.netRealizedPnl(realizedPnlUSD, netFundingUSD, feesUSD)`.

### Currency conversion
USD → EUR via the ECB daily reference rate on `closedDateUTC` (provider, request and cache behaviour: `ARCHITECTURE.md`, Tax report and FX and Browser storage). Weekend/holiday close dates inherit the nearest preceding business-day rate.

When a rate is unavailable for a row's close date, EUR cells render `—` and the row is excluded from EUR totals — never fall back to year-end rate. Single rule, no surprises. `summarize` distinguishes three EUR-coverage states so the on-screen card never reads a misleading `€0.00`:
- `eurRowCount > 0 && eurMissingCount === 0` → full EUR totals.
- `eurRowCount > 0 && eurMissingCount > 0` → numeric totals + `eurPartial: true` (label "partial — missing FX").
- `eurRowCount === 0` → ALL EUR totals collapse to `undefined` (the card renders `—`; label "unavailable").

`convertRowsToEur` is idempotent: each call resets EUR fields and `_fxMissing` on every row before re-applying so re-renders against fresh FX rates always produce a clean result.

Helper: `FxRates.getRates(dates: string[]) -> Promise<{rates, missing}>`. The `dates` array is built from the report's unique `closedDateUTC` values.

### Classification (Categoria E vs G)
The Portuguese fiscal category affects ONLY the totals card label preset and whether the Holding (days) column renders. Row data is identical. The 365-day holding exemption that applies to spot crypto under Categoria G is NOT automatically applied to perp gains: accountants decide on a case-by-case basis.

- `Categoria E (derivativos)`: 28% flat. No holding column.
- `Categoria G (cripto-ativos)`: 28% flat. Holding-days column shown for reference.

Helper: `TaxReport.summarize(rows, classificationId)` — `classificationId ∈ {'E','G'}` swaps labels only.

### Sign convention
**Losses always render as negative dollars.** Helper: `formatCurrency(value)` with negative input. Avg Loss (the card, the Monthly AVG LOSS column and the Payoff caption's "avg win / avg loss") / Trough cum Profit columns must pass `-Math.abs(loss)` so the displayed sign matches the visual loss styling. The Performance-by-Asset WORST column passes the losing trade's own `profit`, which is already negative.

**Zero is neutral.** A value that displays as zero (`$0`, `0.00%`, `$0.00`) carries no sign and no gain/loss colour. This includes the Market tab's current funding APR (`Format.fundingAprClass`) and the Tax tab's fee cells. `Format.formatCurrency` / `fmtSignedPct` decide the sign from the rounded value, and `Format.signClass(value, fractionDigits = 0)` returns `'profit'` / `'loss'` / `'zero'` (muted ink) from the same rounding; every signed cell takes its class from it (`AppDom.updateMetric(id, text, toneClass)` for metric cards). The Current Drawdown card is not a signed cell: its `$0` "At peak" state is deliberately green (see Current Drawdown).

## Positions board

`src/panels/positions.js` renders the Positions tab from `allPositions` (see Per-position attribution); it recomputes no formula. The table lists the most recent `AppConstants.TUNABLES.RECENT_POSITIONS_CAP` closed positions, newest first.
- **CLOSED (UTC)** — `YYYY-MM-DD HH:MM` in UTC (`Format.fmtDateTimeUTC`), the timezone the Tax tab assigns years in.
- **SIDE** — a `⇄` tag on rows opened or closed by a reversing order (`openedByFlip` / `closedByFlip`); its tooltip says the reversing fill's size and fee are split between both rows.
- **SIZE** — `peakSize` in base-asset units, full precision (`Format.fmtAssetSize`: `250 ETH`, `3.14159 BTC`). **ENTRY / EXIT** — `entryVwap` / `exitVwap`.
- **PROFIT** — `profit`, net of fees; funding is the separate FUNDING column (`netFunding`), so PROFIT + FUNDING = net. **PROFIT %** — `tradeReturn × 100`.
- Size, price, profit and return cells render `—` when the position's attribution is incomplete.
- **DURATION** — `Format.formatDuration` (`96d 22h` / `5h 12m` / `12m`), shared with the Behavior tab's hold times.
- **Active Positions** — count of OPEN positions; detail is the open notional, Σ `RiskMetrics.positionNotional` (the Risk tab's leverage definition; needs no subaccount), grouped with thousands separators. While `openPositionsGap` is set the count reads `—` and the detail is that reason; the notional alone reads `—` when any open position has no size or price.
- **Taker Share** (`#positionsTakerShare`) — taker fills ÷ all fills, by count.
- **Hold Time / Position Size Distribution** — labeled rows (label, bar, count) from `renderHistogram`, readable at 390px. Size bins use `RiskMetrics.peakNotional`, the same denominator as `tradeReturn`. The Performance tab's Win/Loss Distribution uses the same primitive over the decisive trades (so its bins add up to the Win Rate card's wins and losses): 2%-wide return bins over ±20% with an edge at 0, each labelled by its range (`-2% to 0%`; the outer bins `< -18%` and `≥ 18%` take everything beyond), red below 0 and green from 0.
